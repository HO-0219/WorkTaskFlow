# 4단계: 도메인 연결 사전 서비스

## 목적

실제 서비스 도메인과 운영에 가까운 인프라에서 내부 테스터가 전체 흐름을 검증한다. 사업자·통신판매업 신고와 실결제가 완료되기 전 단계이므로 유료 판매를 시작하지 않는다.

## 수정할 정보

| 항목 | 사전 서비스 값 |
| --- | --- |
| DNS | 실제 도메인 또는 `staging.example.com` |
| TLS | 실제 인증서와 자동 갱신 |
| `FRONTEND_URL` | 실제 테스트 origin |
| `VITE_PUBLIC_SITE_URL` | 같은 HTTPS origin |
| `AUTH_SECURE_COOKIE` | `true` |
| `MAIL_*` | 실제 도메인 발송 주소, SPF/DKIM/DMARC 확인 |
| OAuth | 운영용 앱과 정확한 Redirect URI |
| Toss | 운영 상점의 테스트키, `TOSS_TEST_MODE=true` |
| `DEMO_ENABLED` | 공개 정책에 따라 읽기 전용만 허용 |
| `VITE_ALLOW_INDEXING` | 출시 승인 전 `false` |
| 개인정보 문의 | 실제 수신·응답 가능한 주소 |

## 서비스 정보 확정

- 서비스명, 운영 주체, 대표 연락처와 고객지원 채널
- 개인정보 보호책임자 또는 담당부서
- 실제 AWS 리전, 메일·OAuth·결제·모니터링 수탁사
- 개인정보 항목별 보유기간과 파기 절차
- 유료 플랜, 가격, 공급 시기, 청약철회·환불 기준
- 장애·보안사고·개인정보 요청 대응 담당자

## 필수 QA

- DNS 전환, 인증서, canonical, OG, favicon, PWA 설치
- `robots.txt`, `sitemap.xml`, 공개/비공개 페이지의 index 정책
- 실제 도메인에서 가입·이메일 인증·비밀번호 재설정
- OAuth 앱 검수·동의 항목과 신규 소셜 가입 동의 흐름
- Toss 테스트 결제수단 등록·승인·실패·재전송·중복 방지
- 고객지원 요청, 동의 철회, 계정 탈퇴, 데이터 익명화
- 부하·장애·DB 복원·배포 롤백 훈련
- 모바일·데스크톱·주요 브라우저 접근성 확인

## 금지 사항

- 운영 결제 시크릿과 `TOSS_TEST_MODE=false` 사용
- 미확정 사업자번호나 통신판매업 신고번호 표시
- 법적 문서를 초안 상태로 두고 일반 고객 대상 유료 판매

## 5단계 진입 조건

- 사업자등록과 필요한 통신판매업 신고 완료
- 결제대행사 운영 심사 및 운영키 발급 완료
- 약관·개인정보 처리방침·환불정책 법률 검토 완료
- 운영 백업·복원, 모니터링, 보안사고 대응 담당자 승인
- 출시 직전 운영 비밀키 신규 발급 및 테스트키와 분리
