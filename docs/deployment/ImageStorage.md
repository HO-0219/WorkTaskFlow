# 이미지 저장: 로컬에서 EC2까지

프로필과 그룹 이미지는 JPG/PNG/GIF, 5MB, 4096px 이하만 허용합니다. 서버는 파일명과 Content-Type을 신뢰하지 않고 실제 형식과 크기를 확인한 뒤 UUID 파일명으로 저장합니다. SVG는 스크립트 삽입 위험 때문에 허용하지 않습니다.

## 로컬

`UPLOAD_LOCAL_ROOT=uploads`가 기본값입니다. 백엔드를 `backend` 디렉터리에서 실행하면 `backend/uploads`에 저장되며 Git에서는 제외됩니다. `/uploads/**`는 JWT 인증을 요구하고 프런트는 인증 헤더로 Blob을 받은 뒤 표시합니다.

## EC2 + Nginx

- 업로드 경로는 배포 파일과 분리한 영속 디렉터리(예: 마운트된 EBS의 `/srv/work-task-flow/uploads`)로 설정합니다.
- 애플리케이션 실행 계정에만 읽기/쓰기 권한을 줍니다.
- Nginx가 `/uploads`를 정적 공개하지 않도록 합니다. 현재 권한 검사를 유지하려면 `/uploads/` 요청도 Spring 서버로 프록시합니다.
- `client_max_body_size 6m;`를 설정합니다.
- 새 릴리스 배포 시 업로드 디렉터리를 삭제하지 않고, 정기 백업과 복구 시험을 수행합니다.

여러 인스턴스로 확장할 때는 저장 구현을 S3로 교체하고, 비공개 버킷·SSE-KMS·짧은 만료의 서명 URL 또는 인증 프록시를 사용합니다. DB에는 저장소 객체 키만 남기는 방식이 적합합니다.
